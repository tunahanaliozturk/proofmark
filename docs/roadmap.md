# Roadmap

Each milestone ends with a test that has to pass. A milestone is not done because the code exists.

| # | Milestone | Scope | Exit test |
| --- | --- | --- | --- |
| M0 | Plan | Repository, lints, CI, design, roadmap, decision records. | CI green on a crate that only prints its name and version. |
| M1 | Wire and signing | HTTP/1.1 client on blocking sockets with optional TLS (`100 Continue`, chunked bodies, `HEAD`, timeouts). SigV4 for headers, presigned URLs and signed chunks. CRC32, CRC32C, CRC64NVME, SHA-256, MD5, base64, the `aws-chunked` encoder and decoder. The fake server's skeleton: bucket and object `PUT`, `GET`, `HEAD`, `DELETE`, with signature checks. Decide `ring` or `aws-lc-rs` (ADR if it changes). | The applicable cases of the aws-c-auth SigV4 suite and the S3 documentation examples pass; a signer that normalises `//` fails them. Every CRC matches its catalogue check value. A signed `PUT` and `GET` round-trip through the fake on all three CI platforms, and a wrong secret gets 403. The response parser survives 10 minutes of fuzzing with no panic and no hang. |

A foreign object written mid-run survives cleanup. A run aborted after N requests, for every N up to the length of the run, leaves a ledger from which `cleanup` removes exactly what the run wrote. The README walkthrough (`proofmark fake` in one terminal, `proofmark run` in another) works on a clean Windows machine. ## Progress

- **M0**, 2026-11-22: done locally. Design, roadmap and five ADRs. The crate prints its name and version; `cargo fmt --check`, `cargo clippy` (warnings as errors), `cargo doc`, `cargo build` and `cargo test` pass on Windows. CI has not run yet, because the repository has not been pushed; the exit test is met on the first green CI run.
- **M1**, 2026-11-25: built and tested locally on Windows; the three-platform half of the exit test waits for the first CI run, like M0. What exists: the HTTP/1.1 client (`src/http.rs`, `src/http/wire.rs`) with TLS through rustls and `ring`, `100 Continue`, chunked and read-to-close bodies, `HEAD`, and one deadline per exchange that covers the name lookup, the TLS handshake and every socket read and write; the SigV4 signer for headers, presigned URLs, chunks and trailers (`src/sigv4.rs`); the `aws-chunked` encoder and decoder (`src/aws_chunked.rs`); CRC32, CRC32C, CRC64NVME, MD5, SHA-256, hex and base64 (`src/checksum.rs`); and the fake server skeleton (`src/fake.rs`): path-style bucket and object `PUT`, `GET`, `HEAD` and `DELETE`, signature, payload hash and chunk signature checks, an early `403` before `100 Continue`, plain HTTP or TLS. `ring` stays; it also supplies SHA-256 and HMAC, and MD5 and the CRCs are written here ([ADR 0007](adr/0007-ring-for-crypto-own-code-for-checksums.md)). The modules sit behind a library target that is not an API ([ADR 0006](adr/0006-library-target-for-tests-not-an-api.md)). Exit test evidence:
  - `tests/sigv4_vectors.rs` passes 32 of the 38 aws-c-auth v4 cases, header and presigned forms, and every worked example in the S3 guide's header, presigned, streaming and trailer pages. The 6 cases left out are the `*-normalized` ones whose paths change when normalised; S3 does not normalise. Replacing `//` with `/` in the canonical URI by hand, which compiled, made `the_applicable_aws_c_auth_cases_pass` fail on `get-slash-unnormalized`.
  - Each CRC matches its check value from crc-catalog 2.5.0 (`each_crc_matches_its_catalogue_check_value`). Changing one bit of the CRC32C polynomial made that test and the S3 trailer checksum test fail.
  - `tests/fake_round_trip.rs`: a signed `PUT` and `GET` of 100,000 bytes round-trip through the fake over HTTP and over TLS, and a wrong secret gets `403 SignatureDoesNotMatch` and stores nothing. Making the fake skip its signature comparison made both wrong-secret tests fail.
  - `tests/fuzz_parsers.rs` ran for 600 seconds in release mode (base seed 1795618928): 365,899,891 inputs, no panic, no hang. Two planted bugs, an unchecked chunk size addition and a body read that loops at the end of input, were caught as a panic and as a hang within the default three-second run. That run was before the review fixes below; after the parser fixes among them, a 120-second run (base seed 1795627095) parsed 68,911,625 inputs with no panic and no hang.
  - The deadline: `a_silent_server_times_out` (a plain TCP peer that never answers), `a_slow_name_lookup_stops_at_the_deadline` (a lookup that takes 3 seconds against a 200 ms deadline returns in time), and `a_tls_peer_that_trickles_the_handshake_times_out_at_the_deadline` and `a_tls_peer_that_trickles_the_body_times_out_at_the_deadline` (a TLS peer that sends one byte every 50 ms, so no single socket read ever times out, is cut off at the deadline). Before the fix both TLS tests waited the full four seconds of the trickle.
  - A read-only review of M1 raised thirteen findings in the code. Twelve were reproduced with a failing test and fixed, one commit each: an escaped `/` decoded in the canonical URI, secrets in `Debug` output, presigning over a caller's payload hash, old `X-Amz-*` parameters signed twice, `101` waited past, head and line limits checked only while reading, chunk-size lines with no digit, NUL in the request head, unbounded name lookups, TLS socket reads that each got a fresh timeout, caller-built TLS configurations, and a fake that could listen beyond loopback. The thirteenth was a missing 63-byte MD5 case; the test was added and the implementation already gave the right digest.
- **M2**, 2026-11-27: built and tested locally on Windows; CI has not run it yet. What exists: the commands `run`, `list`, `explain`, `cleanup` and `fake`, with arguments parsed by hand ([ADR 0010](adr/0010-arguments-parsed-by-hand.md)) (`src/cli.rs`); one run from preflight to report (`src/run.rs`); bucket naming, the empty-bucket check and cleanup (`src/safety.rs`); the JSON-lines write ledger and the cleanup plan read from it ([ADR 0008](adr/0008-what-cleanup-infers-from-the-ledger.md)) (`src/ledger.rs`); the session that signs, sends, records and scrubs (`src/session.rs`); the probe registry, statuses and judges (`src/probe.rs`) and the 14 `basic` probes (`src/probe/basic.rs`); terminal, JSON, JUnit and Markdown output built from codes and counts, with everything written scrubbed of every secret used ([ADR 0009](adr/0009-reports-are-built-from-codes-and-scrubbed.md), [ADR 0013](adr/0013-output-is-scrubbed-at-the-last-step.md)) (`src/report.rs`, `src/cli.rs`); and, in the fake, the faults the `basic` probes catch, listings, ranges and `Content-MD5`. Two dependencies were added, `serde_json` and `roxmltree`; `lexopt` was dropped. Exit test evidence:
  - A non-empty existing bucket: `a_non_empty_existing_bucket_makes_run_exit_3_with_zero_writes` (`tests/cli.rs`) counts the writes the fake receives and compares the store before and after. Making the emptiness check always answer "empty" made it fail.
  - A foreign object written mid-run: `a_foreign_object_written_mid_run_survives_cleanup_of_an_own_bucket` and `..._of_an_existing_bucket` have the fake write someone else's object into the run's bucket as one of the run's own writes arrives. Removing the ledger even when cleanup was incomplete made the first fail.
  - A run aborted after N requests: `a_run_killed_after_any_number_of_requests_leaves_a_ledger_that_cleanup_finishes` kills the binary as each request in turn reaches the fake, lets the fake carry that request out, runs `proofmark cleanup` on the ledger and compares the whole store with how it was, someone else's bucket and object included. The run has 42 requests; 39 of the kills leave something for cleanup to remove. Writing the ledger intent after sending the request, ignoring bucket intents with no outcome, and ignoring object intents with no outcome each made it fail. An earlier draft of this test ended after the second kill without saying so: the flag that told a kill from a normal exit was set after the lock on the child was released, so the test could see the child gone and not killed, and took that as the end of the run. The flag is now set before the kill, under the lock; the test fails if a run it did not kill exits with anything but 0, waits for the fake to finish the request it was handling before cleanup starts, and checks that the kills cover more than 40 requests and that more than 30 of them left something.
  - Every `basic` probe passes on the correct fake and fails on each of its faults: `every_basic_probe_passes_on_the_correct_fake_and_cleans_up` and `every_basic_probe_reports_each_of_its_faults` (`tests/probes.rs`), 15 faults, each with the expected status and silence. Accepting a `200` to a range request and ignoring the status of a `Content-MD5` mismatch each made the second fail.
  - A planted secret: `a_planted_secret_appears_in_no_output` searches stdout, the `--verbose` log, the three report files and the ledger for a planted session token, the secret key and every signature the fake received. Turning off both the name redaction in the log and the scrubbing made it fail. Either one alone is hidden by the other, so each also has its own unit test (`the_log_redacts_secret_headers_by_name`, `scrub_replaces_the_secret_key_and_the_session_token_anywhere`), and turning each off made its test fail.
  - One test per exit code: `exit_0_...` to `exit_5_...` in `tests/cli.rs`, through the real binary. Letting a probe failure win over an incomplete cleanup made `a_leftover_makes_the_exit_code_5_whatever_the_results` fail.
  - The fuzz gate still holds after M2: a 120-second release run of `tests/fuzz_parsers.rs` (base seed 1795782089) parsed 130,799,041 inputs with no panic and no hang.
  - A read-only review of M2 raised 22 findings, four of them high, and judged that M2 did not yet keep its two safety rules: never delete or overwrite data it did not create, and never print a credential. Nineteen were reproduced with a failing test and fixed, two were fixed in the docs, and one moved to M7. The highs: cleanup deleted whatever an edited ledger named (`cleanup_refuses_a_ledger_that_names_data_proofmark_does_not_write`, [ADR 0011](adr/0011-a-ledger-names-only-what-proofmark-writes.md)); `basic.delete-missing` deleted a key the run never wrote, and a kept ledger sent its deletes again over a key written since (`no_probe_deletes_a_key_the_run_has_not_written`, `a_probe_cannot_delete_or_overwrite_a_key_it_did_not_create`, `a_second_cleanup_leaves_a_key_someone_wrote_after_the_first`); a signature echoed into a preflight error code was printed; and the access key id and encoded copies of secrets were not scrubbed (`a_secret_the_store_echoes_into_an_error_code_appears_in_no_output`, `scrub_covers_the_access_key_id_and_encoded_forms_of_each_secret`, [ADR 0013](adr/0013-output-is-scrubbed-at-the-last-step.md)). The mediums: a `501` or an incomplete or wrong listing counted as empty (`the_empty_check_counts_what_it_cannot_read_as_empty_as_not_empty`, [ADR 0012](adr/0012-an-existing-bucket-must-be-shown-empty-and-unversioned.md)); a versioned existing bucket let cleanup leave versions and delete markers and call itself complete (`an_existing_bucket_that_may_be_versioned_is_refused_before_any_write`); a write the store refused was still deleted, and a `CreateBucket` answered with a 5xx was forgotten (`plans_only_what_may_have_been_written_and_not_yet_deleted`); scrubbing rewrote version ids before they went into the ledger (`the_ledger_keeps_a_version_id_exactly_as_the_store_sent_it`); `--use-existing-bucket=false` turned the mode on and a huge `--timeout` overflowed the clock (`a_value_on_a_flag_and_an_endless_timeout_are_usage_errors`); a failed creation that left cleanup work exited 4, not 5 (`a_failed_creation_that_leaves_cleanup_work_exits_5`); a report could be written over the kept ledger (`a_report_is_never_written_over_the_ledger_cleanup_needs`); a report or stdout that could not be written still exited 0 (`a_report_that_cannot_be_written_never_exits_0`, `stdout_that_cannot_be_written_never_exits_0`); and four probes failed stores that behave correctly: lengths and ranges compared as strings, the MD5 ETag expected of SSE-KMS objects, a bucket taken as missing without checking, and a wrong-secret request without the session token (`numeric_headers_are_compared_as_numbers`, `an_object_encrypted_with_kms_or_customer_keys_is_not_judged_by_its_etag`, `the_missing_bucket_probe_judges_only_a_bucket_shown_missing`, `a_request_signed_with_the_wrong_secret_keeps_the_session_token`). The lows: a `501` followed by a lost response came out `inconclusive` (`a_501_before_a_lost_response_still_makes_the_probe_unsupported`); `basic.head` claimed to check that HEAD has no body, which the client never sees, so the expectation no longer says it; and the CHANGELOG said no command used the M1 layer. The M2 medium left open is own-bucket creation with no `LocationConstraint`, listed under M7. Each new test failed before its fix. Mutations tried afterwards: letting the session send any `DELETE` failed `a_probe_cannot_delete_or_overwrite_a_key_it_did_not_create`; making the plan ignore recorded deletes failed `a_second_cleanup_leaves_a_key_someone_wrote_after_the_first`; encoding secrets at one base64 offset instead of three failed `scrub_covers_the_access_key_id_and_encoded_forms_of_each_secret`. After the fixes a 120-second release run of `tests/fuzz_parsers.rs` (base seed 1795787593) parsed 146,663,966 inputs with no panic and no hang.

## Order of work inside a milestone

1. Write the fault in the fake first, and the probe's judge test, and see them fail.
2. Implement the probe until it passes on the correct fake and fails on the fault.
3. Cite the expectation. No citation, no probe.
4. Record any decision that is hard to reverse as an ADR.
